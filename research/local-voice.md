# local-voice
**Question:** Can I talk to a Claude Code session and hear it answer, fully local and free, on this NixOS laptop (Intel Arc iGPU, no NVIDIA)?
**Answer:** Yes, with two small scripts and no new daemon: a push-to-talk key records, `whisper-ctranslate2` (already chosen in share-inbox) transcribes on the CPU and `wtype` types the text into the terminal, and a `Stop` hook pipes `last_assistant_message` to a local text-to-speech. kokoro-onnx is the good-sounding voice, but it is in neither nixpkgs 25.05 nor 26.05, so v0 should speak with packaged `espeak-ng` and treat Kokoro as an upgrade. Claude Code's built-in `/voice` is not local (audio goes to Anthropic), and OpenWhispr is not in nixpkgs and is a heavy Electron app for what a ten-line script does.
**Confidence:** medium, because nothing was timed on this machine, there is no 285H benchmark, and kokoro on NixOS was not run.
**What would change our decision:**
- If Léon accepts audio going to Anthropic and has a claude.ai login, `/voice` removes the whole speech-in half for free.
- If a `uv`/venv wrapper is acceptable for kokoro-onnx (or `piper-tts`, which is on 26.05 only), speech-out quality jumps; if `espeakng-loader`'s bundled espeak does not run on NixOS it needs patching or the system `espeak-ng`.

## Findings
1. **Claude Code's built-in voice is cloud, not local.** `/voice` has hold-to-talk or tap mode. Docs: "Voice dictation streams your recorded audio to Anthropic's servers for transcription. Audio is not processed locally." Needs a claude.ai login; unavailable with an API key, Bedrock, Vertex or Foundry; does not work over SSH; records via a native module, falling back to `arecord` or SoX `rec`. Fails our "local" constraint. [Voice dictation docs](https://code.claude.com/docs/en/voice-dictation)
2. **A `Stop` hook gets the final reply text directly.** Input JSON has `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`, `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons`. `last_assistant_message` "contains the text content of Claude's final response, so hooks can access it without parsing the transcript file". The transcript is written asynchronously and may lag, so use this field. `jq -r '.last_assistant_message'`. [Hooks reference](https://code.claude.com/docs/en/hooks)
3. **`Notification` does not carry the reply**: `message`, optional `title`, `notification_type` (`permission_prompt`, `idle_prompt`, `agent_completed`, others). Fit only for speaking an "I need you" alert. [Hooks reference](https://code.claude.com/docs/en/hooks)
4. **`MessageDisplay` is a streaming alternative**: `delta` (new completed lines), `message_id`, `index`, `final`, so a hook could speak sentence by sentence. Display-only. Latency and whether it fires for every message: UNVERIFIED. [Hooks reference](https://code.claude.com/docs/en/hooks)
5. **whisper-cpp in nixpkgs.** `whisper-cpp` is 1.7.5 on 25.05 and 1.8.4 on 26.05 (MIT), checked with `nix search` on both branches on 2026-11-25. A separate attribute `whisper-cpp-vulkan` exists on both, so no override is needed for the Arc iGPU; whether Vulkan on Arc beats CPU for short clips is UNVERIFIED and untested. No OpenVINO option. [25.05 package.nix](https://raw.githubusercontent.com/NixOS/nixpkgs/nixos-25.05/pkgs/by-name/wh/whisper-cpp/package.nix), [26.05 package.nix](https://raw.githubusercontent.com/NixOS/nixpkgs/nixos-26.05/pkgs/by-name/wh/whisper-cpp/package.nix)
6. **whisper.cpp CPU time.** Published encoder times for the `small` model on a 30 s window: Ryzen 9 3900X (8 threads, AVX2) 2874 ms, Ryzen 9 5950X (8 threads) 1393 ms, i7-11800H (WSL2, 8 threads) 4829 ms. An EPYC 7532 row of about 59 ms is an outlier (build unstated). Whisper pads every clip to 30 s, so a ten-second clip costs about what a thirty-second one does. Estimate for the Core Ultra 9 285H: about 1.5 to 3 s per ten-second clip with decode. UNVERIFIED, no 285H number exists. [whisper.cpp issue 89](https://github.com/ggml-org/whisper.cpp/issues/89)
7. **faster-whisper, the gaps in reel-transcription.md.** `Systran/faster-whisper-small` is MIT; `model.bin` is 484 MB (fp16 file, int8 is applied at load via `compute_type`, so the download is not smaller); repo about 486 MB. This confirms the earlier "480 MB" for small. The faster-whisper code licence (MIT) is stated from memory, UNVERIFIED. Speed: small int8 about 7.6x real time on an i7-12700K, so ten seconds is about 1.3 s there; the 285H is UNVERIFIED (see reel-transcription.md). nixpkgs: `python3Packages.faster-whisper` 1.1.1 / 1.2.1 and `whisper-ctranslate2` 0.5.2 / 0.5.7 (re-confirmed with `nix search`). [HF Systran/faster-whisper-small](https://huggingface.co/Systran/faster-whisper-small/tree/main)
8. **whisper.cpp model sizes (ggml, MIT).** `ggml-small.bin` 488 MB, `ggml-small-q5_1.bin` 190 MB, `ggml-base.en.bin` 148 MB, `ggml-medium.bin` 1.53 GB, `ggml-large-v3-turbo.bin` 1.62 GB. [HF ggerganov/whisper.cpp](https://huggingface.co/ggerganov/whisper.cpp/tree/main)
9. **OpenWhispr is an MIT-licensed Electron dictation app** (hotkey, speak, text lands at the cursor). Local: whisper.cpp for Whisper, sherpa-onnx for Nvidia Parakeet. Also cloud models with your own API keys, and a paid OpenWhispr Cloud (free cloud tier capped at 2,000 words a week; its server side is closed source). Packages: AppImage, deb, rpm, tar.gz, x86_64 only; Node 24+ to build. [Repo](https://github.com/OpenWhispr/openwhispr), [review](https://www.getvoibe.com/resources/openwhispr-review/)
10. **OpenWhispr on Wayland.** It copies text to the clipboard then pastes via a helper. On Wayland the helper needs `/dev/uinput` (membership of the `input` group); fallbacks are `wtype` on Hyprland, Sway and other wlroots compositors and `xdotool` or `ydotool` on GNOME and KDE. Default hotkey Ctrl+Super on Hyprland and KDE Wayland; on Hyprland it binds through `hyprctl`. Hold-to-talk outside GNOME 48+ needs the `input` group, otherwise tap mode. Terminals need Ctrl+Shift+V, so pasting into a terminal is not reliable by default. [Linux platform doc](https://docs.openwhispr.com/platform/linux.md)
11. **OpenWhispr, local-only or cloud, phone-home.** README: "no data collection, no telemetry". Privacy page: with local speech-to-text, audio is not sent anywhere; model downloads (Hugging Face) and updates (GitHub) expose IP, app version and platform. Cloud service logs are kept regardless of the analytics setting (only if cloud is used); the agent web-search feature goes through OpenWhispr to Exa. Which mode is the default, and whether local use needs an account: UNVERIFIED. [Privacy page](https://openwhispr.com/privacy), [README](https://github.com/OpenWhispr/openwhispr)
12. **OpenWhispr is not in nixpkgs.** PR 520102 "openwhispr: init at 1.10.3" is open with no reviewer, so it is on neither 25.05 nor 26.05. A third-party flake `jpe-nix/nix-openwhispr` wraps the AppImage with `--no-sandbox`; not audited. [nixpkgs PR 520102](https://github.com/NixOS/nixpkgs/pull/520102), [nix-openwhispr](https://github.com/jpe-nix/nix-openwhispr)
13. **kokoro-onnx repo, licences, sizes.** thewh1teagle/kokoro-onnx, version 0.6.1 in pyproject. README states the code is MIT (pyproject has no licence field); the Kokoro-82M weights are Apache-2.0. Downloads are separate from the pip package: `kokoro-v1.0.onnx` is 325,505,369 bytes (about 326 MB); quantised fp16 about 164 MB and int8 about 92 MB, but sources disagree (int8 88, 92.4 or 114 MB; fp16 164, 169 or 177.5 MB), so check the release assets; `voices-v1.0.bin` about 28 MB (54 voices). [Repo](https://github.com/thewh1teagle/kokoro-onnx), [releases](https://github.com/thewh1teagle/kokoro-onnx/releases), [HF hexgrad/Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M)
14. **kokoro-onnx dependencies.** `onnxruntime>=1.20.1`, `phonemizer>=3.4.0`, `numpy>=2.0.2`, `espeakng-loader>=0.2.4` (a PyPI wheel bundling espeak-ng), Python `>=3.10,<3.14`. Whether the bundled espeak binary runs on NixOS without patching: UNVERIFIED. [pyproject.toml](https://raw.githubusercontent.com/thewh1teagle/kokoro-onnx/main/pyproject.toml)
15. **kokoro-onnx is not in nixpkgs on either branch.** `nix search` on nixos-25.05 and nixos-26.05 (2026-11-25) finds no `kokoro-onnx`. The only match for "kokoro" is `python3Packages.kokoro` (the hexgrad PyTorch library, needs torch), present on 26.05 for Python 3.13 and 3.14 and absent on 25.05. Its dependencies are packaged: `onnxruntime` 1.22.0 (25.05) / 1.24.4 (26.05), MIT; `espeak-ng` 1.51.1 (25.05) / 1.52.0.1-unstable (26.05), GPL-3.0-or-later. `piper-tts` 1.4.2 is on 26.05 only, not found on 25.05. [onnxruntime 25.05](https://raw.githubusercontent.com/NixOS/nixpkgs/nixos-25.05/pkgs/by-name/on/onnxruntime/package.nix), [onnxruntime 26.05](https://raw.githubusercontent.com/NixOS/nixpkgs/nixos-26.05/pkgs/by-name/on/onnxruntime/package.nix), [espeak-ng 25.05](https://raw.githubusercontent.com/NixOS/nixpkgs/nixos-25.05/pkgs/applications/audio/espeak-ng/default.nix), [espeak-ng 26.05](https://raw.githubusercontent.com/NixOS/nixpkgs/nixos-26.05/pkgs/by-name/es/espeak-ng/package.nix)
16. **kokoro-onnx passes `just vet`.** Cloned at commit 3596b26 to a scratch dir and vetted without installing: MIT licence, no plugin manifest, no hooks, no skills, agents or commands. Network calls appear only in `scripts/fetch_voices.py` (requests to model hosts); outbound addresses in code are developer.nvidia.com, docs.astral.sh, gist.github.com, github.com, huggingface.co, numpy.org and onnxruntime.ai. It reads the environment variables `LOG_LEVEL`, `ONNX_PROVIDER` and `PHONEMIZER_ESPEAK_LIBRARY`. Result: "no blocking findings". The vet is static and found nothing; it says nothing about the model files. [kokoro-onnx at 3596b26](https://github.com/thewh1teagle/kokoro-onnx/tree/3596b26764286a7de9d90c363e988d50578918e5)
17. **kokoro-onnx speed on CPU.** The closest benchmark is a Core Ultra 5 225H under Linux, kokoro-onnx 0.4.7, 15 s passage: int8 3.9x real time (RTF about 0.26), 252 ms to first audio, 529 MB RAM; fp32 1.5x (RTF about 0.67), 651 ms to first audio, 824 MB. For ten seconds of speech that is about 2.6 s (int8) and about 6.7 s (fp32). UNVERIFIED for the 285H, which has more cores. Short utterances are worse: one AVX2/AVX-512 laptop took 2.0 s for a 0.83 s clip (RTF 2.41), so long replies run in real time and short ones may not. Other reports: M3 Pro about 6x, unspecified hardware RTF 0.5 to 0.64. [kokorolake benchmark](https://github.com/sortedcord/kokorolake), [decafclaw issue 1281](https://github.com/lmorchard/decafclaw/issues/1281), [heyneo benchmark](https://heyneo.com/blog/kokoro-supertonic-inflect-nano-pocket-tts-cpu-benchmark)
18. **Push-to-talk typing on Wayland.** `wtype` 0.4 (both branches, `nix search`): `wtype "text"` types via the virtual-keyboard protocol, no daemon or group; works on Hyprland and other wlroots compositors, but OpenWhispr's docs list only xdotool or ydotool for GNOME and KDE, so it likely does not work on the teammates' KDE Plasma (UNVERIFIED). `wl-clipboard` can only copy; pairing with a paste keypress needs Ctrl+Shift+V in terminals. `ydotool` 1.0.4 (both branches) works on any compositor via `/dev/uinput`; on NixOS `programs.ydotool.enable = true;` plus the `ydotool` group and a re-login, a system-level change; one report that `type` and `key` did nothing from Hyprland binds on 0.45.2 (no resolution seen). Hold-to-talk needs key-release events: Hyprland `bind` / `bindr`, record on press and transcribe on release; the Plasma equivalent was not checked. [wtype](https://github.com/atx/wtype), [Linux platform doc](https://docs.openwhispr.com/platform/linux.md), [NixOS ydotool module](https://github.com/NixOS/nixpkgs/blob/release-26.05/nixos/modules/programs/ydotool.nix), [ydotool issue 290](https://github.com/ReimuNotMoe/ydotool/issues/290)
19. **The smallest way to do it (proposal, untested, nothing built).** Speech in: a Hyprland `bind` / `bindr` pair runs `pw-record` to a WAV on press; on release `whisper-ctranslate2 --model small --compute_type int8` transcribes (the choice share-inbox already made) and `wtype -- "$text"` types it into the focused Claude Code prompt, leaving the human to press Enter. Speech out: a `Stop` hook runs `jq -r .last_assistant_message | espeak-ng` in the background, guarded by `stop_hook_active` and a mute file so it can be switched off. Packaging cost: zero new packages on Léon's 25.05 (`whisper-ctranslate2`, `wtype`, `espeak-ng`, `pipewire` are all there); the Kokoro upgrade needs a `uv`/venv wrapper or a small nixpkgs package and is a later step. KDE teammates swap `wtype` for `ydotool` and need a Plasma shortcut instead of the Hyprland bind. A first build is two scripts plus one hook entry in this module.
