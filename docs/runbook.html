Research Runbook

Five research prompts from your reels, shorts and notes, each with the model, effort level and folder it runs in. Copy the launch command, paste the prompt, and come back to me when it's done.

1 · Open a terminalAny terminal. Every launch command below starts with the cd it needs, so you never have to think about the folder.
2 · Copy, paste, enterCopy the launch command and run it. When Claude Code opens, copy the prompt and paste it as your first message.
3 · Tell me it's doneEach result lands in research/ in claude-env. Tell me which one finished and I'll put it on the board.

The order that wastes the least time

  1. Start 3 and 4 first, in two separate terminals. They're broad searches that run on their own, so they can work while you do the rest.
  2. Then sit down for 1. It's the only conversation. It asks you questions and takes about an hour.
  3. Run 2 whenever you like. It doesn't depend on anything.
  4. Run 5 only after 1. It reuses what 1 decides about transcription.

The share-to-Claude inbox

How anything you see on your phone or laptop reaches Claude in one or two taps, gets checked for safety and usefulness, and lands in memory and your todos. It covers your Pixel and Almar's iPhone. This is a design conversation: it will ask you things, so stay at the keyboard.

Launch command
cd ~/Projects/claude-env && claude --model opus --effort high --add-dir ~/Projects/crew-memory ~/project-brain
Prompt, as your first message
Design a share-to-Claude inbox. When I see a reel, TikTok, post, repo or website on my phone or laptop, I send it in one or two taps. Claude fetches it, checks whether it's safe and useful, scores it, and if it's worth it, files it in crew-memory's Ideas store and adds a todo. It has to work on Android (my Pixel 10) and iPhone (Almar's), and when my laptop is off.

Starting position, which you should challenge rather than accept: a small share receiver on our Contabo VPS (FastAPI + SQLite behind Caddy). Android gets an installable web app that appears in the share sheet; iPhone gets a built-in Shortcut in the share sheet; each person has their own key so what they share is recorded as theirs. A laptop-side /inbox skill fetches, judges and files.

Reference picture: the 8 slides in ~/Downloads/social-media-downloads/tiktok-post-by-@chase_ai_/. Map what we already have (Laya as the router, crew-memory, project-brain, the schedule skill) before proposing anything new.

While you read crew-memory, have the researcher agent answer two questions in parallel, each filed by doc-writer in the deliverable format from research/PROGRESS.md:
1. research/reel-transcription.md: how a public Instagram or TikTok video's audio becomes text on this machine for free, using yt-dlp and faster-whisper on CPU. Is each in nixpkgs, is it fast enough on an Intel Arc laptop, and does yt-dlp need my login for Instagram?
2. research/agent-reach.md: how Agent Reach reads X, Reddit and LinkedIn without APIs. Whose cookies, which terms it breaks, the account-ban risk. Clone it to a scratch dir and run `just vet` on it; don't install it.

Then give me the design: capture → fetch → judge → file, one component per step, plus the smallest v0 I could use this week. Ask me about anything you'd otherwise guess. Don't build yet.

Done when you have a design you agree with, and research/reel-transcription.md and research/agent-reach.md exist. Nothing gets built in this session.

Why these models and efforts

ModelOpus 5.5Efforthigh

For judgement calls: a design (1) and "is this safe?" (2). These are the answers you can't check at a glance, so they get the strongest reasoning.

ModelSonnet 5.5Effortmedium

For search-and-compare (3, 4, 5). The researcher agent that does the searching is set to Sonnet anyway, so a pricier session around it would only add cost.

Never xhigh or max

Nothing here is hard enough to need them. They use up your weekly allowance faster and don't make a search more thorough.
