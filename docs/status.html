Goal

A shareable NixOS flake that gives Léon and his friends the same Claude Code environment — every MCP server, skill, agent and guardrail available in every project folder — with a Blitsol tier for the people who also work on the company.

Not this

  • Sharing Léon's personal nix-config — hardware, Borg backups, host secrets
  • Handing friends Blitsol credentials by copy-paste instead of inviting them into the real accounts
  • Adding an MCP server where a CLI already does the job better
  • Rebuilding the Claude config as dotfiles; it is already home-manager and stays that way
  • Building the shared crew memory system — its own project, crew-memory, designed 13 Nov; this one ships the tools it needs
  • Building the booking starter or the client legal-document generator — real gaps, their own repos
  • Hosting CLM — parked 16 Nov: the bf16 path needs a 24 GB card and no crew laptop has more than 6 GB

Base and Blitsol tiers

tiers

One option — claude-env.tier = "base" | "blitsol" — decides whether a machine gets the company server on top of the shared toolkit.

DoneAsserted by just test on both releases: base resolves to atlassian, context7 and playwright exactly; blitsol adds cloudflare. Six opt-in modules are wired and all default off.
JudgementNo tiers.nix. The tier is read where it has an effect — mcp.nix and the CLAUDE.md header — and a file that only re-exports a boolean would be a layer with nothing in it.
LeftThe secrets half, which waits on nobody now that the keys are collected: see secrets-delivery.

Make mcp.nix the single source of truth

mcp-declarative

mcp.nix used to ship a setup-claude-mcp.sh that had to be run by hand, so user-scope servers drifted the moment anyone typed claude mcp add. That drift is exactly what happened — twice.

DoneA claude-mcp helper rewrites the mcpServers block of ~/.claude.json from Nix on activation and prunes local-scope duplicates, merging the rest of the file rather than replacing it. The script is deleted. 44 of the 134 script tests cover this one helper.
Escape hatchRemovals are named on stderr and written to ~/.claude/removed-mcp-servers.json before they go, so "it worked yesterday" has an answer. Keeping one means declaring it — in the module for all four laptops, or claude-env.mcp.personal for one.
CarefulIt declines to create a missing ~/.claude.json, because inventing an account-less state file is worse than waiting: start Claude Code once, then switch again.

Consolidate the 39 scattered MCP servers

mcp-consolidate

Servers were split across three local scopes plus user and project scope, which is why the web-design toolkit was invisible everywhere except one directory.

DoneTwenty-three registrations dropped with a reason each, four declared, six behind opt-in flags. CLI-first held: no github server because gh --json --jq is cheaper and already authenticated, no filesystem server because it could not see ~/Projects anyway, no memory server because the crew keeps one file-based memory system.
CorrectedThree claims in docs/mcp-audit.md were wrong and were found by wiring the servers rather than reading about them: moneybird is gone with the bookkeeping switch, overheid-apis does not exist on npm, and vies-vat was attributed to the wrong author.

The flake must carry the security guard

guard-portability

The guard is a NixOS system module, separate from the home module — so shipping only the home half would hand friends every skill, agent and MCP server with none of the deny rules on .env, /run/agenix and SSH keys.

DoneThe flake exports nixosModules.default alongside homeManagerModules.default, just test evaluates the managed settings on both releases, and §1 of the guide says to import both and spells out what taking the home module alone actually means.
FixedOne false positive, found by hitting it twice. The force-push rule read the whole command string, so a commit message containing +0 looked like a +ref refspec and a -f belonging to an earlier rm looked like --force — both blocked an ordinary push to main. The flags are now looked for inside the push command itself, while the branch name is still looked for in the whole string, because switching to main and then force-pushing really is one act. Seven cases cover it.

The guide for friends

friend-guide

A friend needs to know what exists, when to reach for which skill or agent, and what the guardrails will stop him doing. None of that is discoverable from the flake.

Donedocs/guide.md in nine sections: install and how to check it took, the two tiers and the six opt-in modules, the full inventory, how to add your own things, the deny and ask lists, vetting with claude-vet, the first hour as seven ordered steps, a symptom table, and four house rules. Every command says which directory to run it in.
Anddocs/enrolment.md for the Blitsol half: adding and revoking a person, host key versus personal key, the recipient count check that needs grep -ac because age files are binary, and a fourth revoke step that is actually security — re-keying does not un-leak, so values get rotated at source.
Untested claimThat a friend can follow it without asking Léon a question. That is onboarding-test.

Closed 20 Nov. There is no longer a document to disagree with the code: the module writes the server list on activation, so the only way to keep a server is to declare it. The same fix is now applied one layer up to plugins.
