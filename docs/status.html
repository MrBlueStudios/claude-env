  • Handing friends Blitsol credentials by copy-paste instead of inviting them into the real accounts

Make mcp.nix the single source of truth

mcp-declarative

mcp.nix used to ship a setup-claude-mcp.sh that had to be run by hand, so user-scope servers drifted the moment anyone typed claude mcp add. That drift is exactly what happened — twice.

DoneA claude-mcp helper rewrites the mcpServers block of ~/.claude.json from Nix on activation and prunes local-scope duplicates, merging the rest of the file rather than replacing it. The script is deleted. 44 of the 144 script tests cover this one helper.
Escape hatchRemovals are named on stderr and written to ~/.claude/removed-mcp-servers.json before they go, so "it worked yesterday" has an answer. Keeping one means declaring it — in the module for all four laptops, or claude-env.mcp.personal for one.
CarefulIt declines to create a missing ~/.claude.json, because inventing an account-less state file is worse than waiting: start Claude Code once, then switch again.

The flake must carry the security guard

guard-portability

The guard is a NixOS system module, separate from the home module — so shipping only the home half would hand friends every skill, agent and MCP server with none of the deny rules on .env, /run/agenix and SSH keys.

DoneThe flake exports nixosModules.default alongside homeManagerModules.default, just test evaluates the managed settings on both releases, and §1 of the guide says to import both and spells out what taking the home module alone actually means.
FixedOne false positive, found by hitting it twice. The force-push rule read the whole command string, so a commit message containing +0 looked like a +ref refspec and a -f belonging to an earlier rm looked like --force — both blocked an ordinary push to main. The flags are now looked for inside the push command itself, while the branch name is still looked for in the whole string, because switching to main and then force-pushing really is one act. Seven cases cover it.
